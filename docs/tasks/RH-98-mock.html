RH-97 — Stop discarding song edits silently

The edit form today lets a musician retype any catalog value, reports success, and the database quietly keeps the old one. Below: the shape the spec proposes, the one open question, and the notice that fires when a refusal slips through anyway.

Read-only shared fields

The question: a song's title, artist, album and cover belong to the shared catalog — everyone who has that song sees the same values. Once one of them has a value, you can no longer type over it here; you suggest a correction instead. Which way should those fields look while you cannot type in them? A shows the value as plain text, like a fact being stated. B keeps the input box, greyed out. The spec currently picks A, because a greyed box reads like something that is broken or still loading, while plain text reads like information. Reply with one letter.

When a refusal slips through anyway

The form is drawn from what the catalog held when it opened. If someone else fills a value in the meantime, the save can still be refused — and this is what replaces today's false "Saved".

Your status and tags were saved. Two catalog values were not.

  • Links catalog has 1 link, you entered 2

The button opens the correction form already holding the values that were refused — nothing has to be retyped.
