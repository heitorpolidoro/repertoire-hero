RH-147 — Which of a song's files is the primary one?

Four questions, each with the options side by side on the real Fast View “Tabs” section. The first panel of Q1 is today's behaviour. Answering with a letter per question is enough — A or B (Q4 also offers C).

Q1 — Designation or ordering?

Do you want one file marked as “the one I play from”, or do you want to put the whole list in the order you like (and the top one is the primary)?

Today a song's files are listed newest-upload-first and none of them is marked. Both options are personal: a band mate never sees or changes your choice.

0Today

Newest upload first. Nothing is marked. Nothing can be set.

Tabs

Viewing: Chord chart (capo 2)

AOne file is marked

A star on each row. One tap moves it. Exactly one file per song can wear it. Whether the starred file also moves to the top of the list is a separate choice — that is Q3.

Tabs

Try it: tap a star. Smaller change. Answers only “which one”, and the database itself forbids a second primary.

BYou order the whole list

A drag handle on each row, the same as a setlist. The top file is the primary one.

Tabs

Try it: drag a row by its dots. Bigger change — a reorder is several rows rewritten at once — but you get the ordering too, and the top row is always the primary.

Q2 — What is already primary, for files you uploaded before this change?

For a song that already has several files, which one should start out as the primary — the first chart you ever uploaded, or the most recent one?

Today’s state is the panel marked 0 in Q1 above: newest first, nothing marked. This runs once, for everybody, and is what you will see on your next visit. The same rule then decides what happens when you upload a new file onto a song that already has one.

AThe oldest file

The first chart you uploaded for the song. A new upload later does not steal the primary.

Tabs

  • uploaded today
  • last month
  • a year ago

The chart you have played from longest wins, even though it sits at the bottom of the list.

BThe newest file

Whatever is at the top of the list today. A new upload later becomes the primary.

Tabs

  • uploaded today
  • last month
  • a year ago

Nothing appears to move, and a phone photo taken at rehearsal immediately becomes what opens.

Q3 — Does the primary file move to the top of the list?

Should the primary file jump to the top of the file list, or stay where it is with a badge on it?

Today’s state is the panel marked 0 in Q1 above: newest first, nothing marked. Shown here with the oldest chart as the primary, which is the case where the two differ most.

APinned to the top

Primary first, everything else newest-first below it.

Tabs

The file that opens is the first one you see. Rows move when you change the primary.

BMarked where it is

List order untouched — newest first — with a badge on the primary.

Tabs

Nothing you have learned moves, but the file that opens can be the last one in the list.

Q4 — Where do you tap to set it?

Should the row carry a star you tap directly, or a “⋯” menu that holds “Set as primary”? (Option C is what Q1-B would give you instead: a drag handle.)

Today’s row — the panel marked 0 in Q1 above — holds select / open / delete and no set-primary control. Every option is disabled while you are offline, like the delete button already is — flip the switch under each panel to see it.

AA star on the row

Three controls per row: star, open-in-new-tab, delete.

BA “⋯” menu on the row

Two visible controls; “Set as primary” and “Delete” live in the menu.

CA drag handle (only if Q1 = B)

No per-row verb at all — you drag the row you want to the top.

📴 Offline the app is read-only: setting a primary is disabled, selecting and reading a file are not.
