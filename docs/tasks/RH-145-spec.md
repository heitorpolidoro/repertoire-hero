# RH-145 — Group a song's links by provider, expanding only when there are several

## Scope
Presentation change in Fast View's Links section only (`LinksSection`, the one surface that lists a song's links today). Links are grouped by the authoritative `SongLink.provider` (`spotify` | `youtube` | `other`, generated by the schema in RH-136); no url classification is added and no column is touched. Not included: add/delete behaviour, RH-138 per-row corrections, RH-143 (dropping `songs.links`), the Spotify push/import, any other screen.

Decisions:
- Groups exist for `spotify` and `youtube` only. Links with `provider = 'other'` (chord sites, Drive, PDFs) stay separate rows as today; a link whose `provider` is absent is treated as `other`. The provider is never null in the database.
- A provider with exactly one link renders as a plain row that opens the link on the first tap (no confirmation). With several links it renders one row showing the provider name and count; tapping it expands the links in place, and the musician picks one.
- Order between groups: Spotify, YouTube, then the `other` rows. Order within a group and among `other` rows: `position, created_at, id` as the controller already supplies (no re-sorting).
- Delete stays per link: on a single-link row as today, on each link inside an expanded group. A group row itself has no delete.

## Approach
Behavior: a pure helper partitions `controller.links` into ordered entries (single link, multi-link group, other link); `LinksSection` renders each with the existing Link Card styling and a chevron/count on groups. Expansion is local UI state, collapsed by default. Offline read-only (RH-99) still disables delete and add but not opening or expanding.

Files touched:
- `src/lib/songLinks.ts` — add the pure grouping helper (provider fallback to `other`, fixed provider order, input order preserved).
- `src/components/fastview/LinksSection.tsx` — render single rows, expandable group rows and other rows.
- songLinks helper test under `src/lib/__tests__/` — helper cases.
- `src/components/fastview/__tests__/LinksSection.test.tsx` — update existing, add grouped cases.
- `package.json` — version bump per AGENTS.md.

Test criteria, fixture "mixed song": Spotify x1; YouTube x3 supplied in order A, B, C; two `other` links; one link with no `provider`.
- Helper returns [Spotify single, YouTube group A,B,C, then the other rows incl. the provider-less one], in that order.
- A single-link row is an anchor to the url; a group row is a button without href that reveals three anchors.
- Delete inside a group calls `onDelete` with that url; read-only disables delete but not expand.

Mock: `docs/tasks/RH-145-mock.html` (Question 1: other links; Question 2: one-link behaviour). Not a landing-page selling point.

## Expected Results
- [ ] In Fast View, Spotify and YouTube links render grouped by `provider` rather than one row per link.
- [ ] A provider with exactly one link renders an anchor to that url, opening on the first tap with no intermediate list.
- [ ] A provider with several links renders one collapsed row that, when tapped, lists every link of that provider as an anchor.
- [ ] Links with `provider = 'other'` (or no provider) remain separate rows.
- [ ] For the "mixed song" fixture the rendered order is Spotify, YouTube, then other rows, with a group's links in input order.
- [ ] Deleting a link inside an expanded group calls `onDelete` with that link's url, and is disabled when read-only.

## Out of Scope
Other surfaces, link editing, reclassifying urls, the column changes of RH-138 and RH-143.
